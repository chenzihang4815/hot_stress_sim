# 论文证据：实验设计、计算、结果图

这份只列已经落在 `论文证据/` 里的实验。每一节写三件事：设计、计算、图在哪。数字都指向该目录自己的 README 或 json，这里不另算一遍。

温度有四种口径，不能放进同一张表：

- **TAP HotSpot**：`TAP-2.5D/util/hotspot`（607163 字节，2025-12-13）。detailed_3D，读芯粒层峰值。
- **闭环 HotSpot**：`任务仿真产生功耗文件工具/HotSpot-master/hotspot`（276152 字节）。两个二进制不要混。
- **ATSim**：冻结布局之后的有限元。温度是芯粒层最热一格 `die_cell_max_C`，不是块平均。应力是芯片内部 von Mises 最大，**没有**乘 0.892047。那个系数只在 `热应力python工程_最终/scripts/run_case2_stress.py` 和 `run_case3_stress.py`。
- **Python 场**：绝对摄氏度偏高，只能做同一算子内部的差、占比、接受与否。三套 Python 算子彼此也不能比绝对温度，见下一节。

不引用的数（两表对照、四列对照、场叠加对照的 README 都写了）：7.27 倍、89468.8 s、151.86 °C、46.3 倍、5014.8 s、8.4 / 7.1 / 9.0 倍。

micro150 的 64 网格 +2.49 °C 用种子 22。种子 23 重跑是 99.40 °C，不拿来替换。

## 1. `tap场叠加/` — TAP 自己的退火

README：`tap场叠加/README.md`。

**设计。** 退火、移动、起点都是 TAP-2.5D 自己的代码，TAP 目录里的文件没有改。起点是 `system.initial_placement` 的 B*-tree。种子 22 在生成起点之前设，全解和场叠加的初始布局逐字节相同。移动是 `close_neighbor` 和 `jumping_neighbor`。接受只按峰值温度。TAP 原版还加权线长，线长用 CPLEX，这台机器没有，所以用的是 `sim_annealing.py` 第 106 行注释掉的只按温度的版本。120 步：温度从 1.0 起，每 50 步乘 0.8。三案：ascend910、micro150、multigpu。

**计算。** 求解器是 TAP 的 HotSpot。全解每步一次求解。场叠加把每个芯粒单独的温度场缓存再相加，没移动的芯粒不再求解。16 网格搜索的赢家回到 64 网格重评，热图用这次重评。64 网格那一批搜索和重评是同一个网格，没有另做重评。

**结果（64 网格峰值）。** 16 网格搜索：ascend910 75.10 → 全解 73.98 / 场叠加 74.02（+0.04），用时 49.6 s 对 25.1 s，1.98 倍。micro150 113.40 → 97.97 / 97.97，1.49 倍。multigpu 97.51 → 92.69 / 92.69，1.81 倍。64 网格搜索：ascend910 73.95 / 73.95，2.08 倍；micro150 97.81 / 100.30，**+2.49**，1.54 倍；multigpu 92.67 / 92.69，+0.02，1.84 倍。+2.49 不是求解误差：第 62 步全解 102.62 °C 拒绝、场叠加 102.60 °C 接受，差 0.02 °C 压在阈值上，后面分叉。

**图。**

- `图/{案例}_120步_{full,field}.png`：16 网格。
- `图/{案例}_120步_64_{full,field}.png`：64 网格。每张并排初始和最优，左右共用色标。

原始输出在 `runs/{案例}_{16,64}_{full,field}/`。

**口径。** TAP HotSpot。不和 Python 场、不和闭环的 HotSpot 二进制混。

### 1.1 同目录的 TIM 老化重放

不重新退火。布局、移动、接受与否从 `runs/{案例}_16_full/trace.json` 读回来，三种热条件走同一条路。求解器仍是 TAP 的 HotSpot。老化：TIM 厚度不变，电阻率 0.25 → 0.75，比热 4.00E6 → 1.333E6。次散热：`model_secondary`，中介层下加衬底、焊球、PCB，PCB 底面对 45 °C，`r_convec_sec` 0.00225。温度是 **16 网格**峰值，不是上面的 64 网格重评。

## 4. `闭环全流程/` — 12 案例，变差步按概率收

README：`闭环全流程/README.md`。

**设计。** 5、6、7、8、9、11 颗，硅和环氧各一，共 12。每案是 CPU + GPU + CIM。起点是 bstree、mcts、lbfgs 三个里 ATSim 评分最低的，记在 `起点/选择.json`。40 步，全部用场叠加（算子 A）。改芯片的比例在套件里是 10%。默认变差步接受概率 `0.20 × (1 − step/N)`，代码在 `run_closed_loop_suite.py` 第 525–529 行。`SUITE_WORSE_P=0` 才是只收不差于当前的，那是下一节，不是这一节。

**计算。** 接受用的温度是算子 A 的峰值，归一化：温升 `(T−45)` 、梯度、线长各除以起点，三项平均。均匀抬升会被消掉；跟功耗或填充有关的抬升消不掉。应力不进接受。ATSim 在退火结束后跑三次（起点、最优、调频后），2 mm 网格，一次 35–65 秒，12 案串行。`anneal_stress.json` 是事后补的，只补被接受的步。
