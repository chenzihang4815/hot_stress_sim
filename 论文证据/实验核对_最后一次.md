## 2. 填充对主次散热，以及老化

工具是五层 Python，`run_interposer_map.solve_with_interposer`。不是 HotSpot，不是 ATSim，也不是后来补上 8 个外伸节点的四层算子。绝对温度不和 HotSpot、ATSim 放进同一张表。这一组没有按外伸环重画。

## 4. 完整闭环里谁被调用

搜索本身是 2026-11-17 的那一次。`report.json` 的时间是当天 16:30 和 18:35。搜索没有重跑。

当时每一步的目标值用的是 Python，而且是还没有外伸环的那一版。环氧那几趟更窄：矩阵按整层硅分解一次，缝的差别用一个冻住的初值残差，不是每步按环氧重分解。所以环氧搜索当时的标价，不是今天图上的环氧温度。

2026-11-18 中午只做了重解，没有重搜。已接受的布局用带环的四层算子再解了一遍。硅填充是一次分解套全部布局。环氧是每个布局按 k=0.8 重画再解。热图、对比图里的 Python 柱、退火曲线上的温度、帕累托云，都是这次重解。线长和搜索当时的目标值仍是旧记录。红线仍是旧搜索按目标值选出的那一个布局，温度换成了新解。`python_ring.json` 写明没有覆盖 `fields/*.npy` 和 `report.json`。

HotSpot 柱是 `任务仿真产生功耗文件工具/HotSpot-master/hotspot`，不是 TAP 那个二进制。配置是 96 mm 均热片和热沉，`r_convec` 0.0390625，芯片层导热固定 130，所以缝的填充在 HotSpot 里看不见，次路径关着。这列没有重跑。

ATSim 在布局冻住之后做门槛，搜索过程里不进接受。温度门槛是芯粒层最热一格，不是柱平均，也不是 Python 热图上的最高格。应力门槛是芯片上的 von Mises，不乘 0.892。0.892 只出现在 V-A 和 COMSOL 的对比里，`VM_SCALE` 只在 `run_case2_stress.py` 和 `run_case3_stress.py`。HBM 不进应力门槛。ATSim 这列也没有重跑。

频率是布局冻住之后的另一段。倍率 0.5 到 2.5，步进 0.1，只缩动态功耗。2.5 是上限。12 个碰到上限的案例，频率是被这个上限挡住的，不是搜索自己停在那里。不限频率的那一次在 `闭环全流程_只收更优_不限频率`，布局是冻住的，没有新的退火。n5 硅在那一次里频率放到 20.7 倍，芯粒格最高 101.12 °C，门槛没有过。

并排图上的三根温度柱不是同一个量。Python 柱是最热芯片的块平均。HotSpot 柱是块平均，而且缝按硅。ATSim 柱是芯片柱平均。门槛用的芯粒格最高温不在这根柱上。

帕累托云是环氧 0.8 加外伸环，在原来的布局样本上重解的，不是新的搜索。线长先和 `scan.json` 对过。n5、n7、n9 是 400 次试探，n11 磁盘上是 300 次，脚本后来写成 400，没有补跑。重解之后的前沿是 n5 10/414、n7 12/395、n9 11/401、n11 14/301。当初按硅扫描挑出的 18 个 ATSim 布局没有重解。

另外一次，2026-11-18 下午，只为看同一布局上 Python 和 ATSim 差多少。布局和功耗取 `闭环全流程_只收更优` 的 `best.json`，硅，倍率 1，只算温度，不算应力。数据在 `同布局_python对atsim/`，不替换闭环报告。

5 颗，164.86 W。Python 芯片层最高格 61.49 °C，ATSim 芯粒格最高 61.26 °C，差 +0.22 K。五颗芯片的块平均，Python 比 ATSim 柱平均高 0.24 到 0.99 K。

7 颗，249.3 W。Python 65.15 °C，ATSim 64.22 °C，差 +0.93 K。七颗的块平均高 0.22 到 1.66 K。

冷热的次序两边一致。差随功耗变大，不是一个可以拿来换算的常数。ATSim 比 Python 多了 1 mm 有机衬底和 100 µm 硅中介层，芯粒区 2 mm、外围 8 mm，而且这一次热求解用的是常导热，不是随温度变的导热。
